# Ovoko - pierwszy test odczytu

- Panel `/panel/ovoko`, link widoczny tylko administratorom. API osobno sprawdza uprawnienia i zawieszenie konta.
- `GET /api/ovoko/status` sprawdza tylko dostep lokalny, bez kontaktu z Ovoko.
- `POST /api/ovoko/test` przyjmuje login, haslo i user_token z formularza i wywoluje WYLACZNIE `POST https://api.rrr.lt/get/car_brands` jako form data. Nie przyjmuje docelowego URL ani operacji od klienta. Redirecty sa blokowane.
- `POST /api/ovoko/read` wykonuje JEDEN wybrany odczyt z zamknietej listy: modele (`/get/car_models/{brandId}`), kategorie (`/get/categories`), statusy (`/get/part_status`), jakosc (`/get/part_quality`) lub podglad magazynu (`/v2/get/parts?page=1&limit=20`). BrandId musi byc dodatnim ID liczbowym; UI pozwala wybrac marke z poprzedniego odczytu. Operacje zapisu, adresy od klienta i dowolna paginacja nie sa obslugiwane. Zmiana wyboru w formularzu nie wykonuje zadania.
- Modele: sprawdzamy zgodnosc marki. Kategorie: zachowujemy poziom i rodzica; nie dopasowujemy kategorii Allegro automatycznie. Statusy i jakosc sa obiektami indeksowanymi ID, nie tablicami; ID 0 zachowujemy. Nazwy PL z EN jako alternatywa. Nieznany lub niepelny format oznacza blad, nie sukces.
- Magazyn: tylko `data` i plaska `pagination` zgodnie z przykladem oraz uwaga w przewodniku (schema Swagger blednie opisuje podwojne zagniezdzenie pagination). Weryfikujemy limit, strone, liczbe rekordow i unikatowosc ID. Pusty magazyn jest poprawny tylko z total_count=0. Pokazujemy wybrane pola: ID, nazwe, car_id, category_id, manufacturer_code, external_id, price, status, quality. Nie zwracamy wewnetrznych notatek, danych rezerwujacego, galerii ani linkow dostawcy. Brak potwierdzonej waluty oznacza surowa wartosc bez PLN/EUR. Podglad NIE jest pelna kopia magazynu i NIE potwierdza samodzielnie tozsamosci sprzedawcy. Nie tworzymy powiazan z Allegro.
- Nie ma zapisu danych API w bazie, cookies, localStorage ani sessionStorage. Pola hasla i tokena sa czyszczone po probie. Nie logujemy danych, surowych odpowiedzi ani bledow dostawcy. Do stalego polaczenia bedzie potrzebny osobny etap z szyfrowaniem i rozdzieleniem kont.
- R200 oraz prawidlowa lista marek oznaczaja poprawny test odczytu. HTTP 200 samo nie wystarcza. R013 oznacza odrzucenie IP. R202 i niepelne odpowiedzi nie sa uznawane za sukces.
- Wynik NIE potwierdza wlasnosci magazynu, uprawnien do importu ani braku ograniczen konkretnego szablonu dostepu. Dopisek Partlinker nie jest automatycznie interpretowany jako blokada ani jako gwarancja pelnego dostepu.
- Brak importu, callbackow, cronow, zapisu ofert, zmiany stanow/cen i konczenia ofert. Istniejacy Wystawiacz, beta, Allegro i platnosci pozostaja bez zmian.
- Kill switch `OVOKO_TEST_ENABLED=false`. Wspolny limit 3 prob/min/admin na instancje Workera (nie jest limitem globalnym). Formularz do 8192 bajtow, odpowiedz testu marek do 512000 bajtow, pozostalych odczytow do 2000000 bajtow; 20 s timeout, bez automatycznych ponowien. Wymagana zgodnosc Origin; sesja Supabase z potwierdzonym e-mailem.
- Dane ujawnione na zrzutach powinny zostac wymienione przed uzyciem. Nigdy nie zapisujemy ich w repo ani fixture testowych.

Zrodlo: https://api.rrr.lt/docs/integration_guide.php - sekcje 2 i 3.

Rozszerzenie odczytu sprawdzone 2026-11-20: sekcje 7.2-7.5 tego przewodnika; https://api.rrr.lt/openapi/swagger.yaml (exampleGetPartsV2); strony /docs/car_models.php, /docs/categories.php, /docs/part_status.php i /docs/part_quality.php. Przed zapisem pozostaje sprawdzic obowiazkowe atrybuty zalezne od kategorii, mapowanie auta/czesci, walute, wysylke, uprawnienia i tozsamosc magazynu. Sam odczyt nie rozstrzyga tych kwestii.

Testy: `node scripts/test-ovoko.mjs`, `node scripts/test-ovoko-worker.mjs` oraz `node scripts/test-ovoko-browser.mjs` (PLAYWRIGHT_MODULE wskazuje runtime). Dane i zewnetrzne zadania sa atrapami. Test worker uruchamia prawdziwy workerd: weryfikuje odczyt i blokade HTTP 301/302/303/307/308 bez przekazywania sekretow. Uzywamy redirect: manual, poniewaz Workers nie obsluguje redirect: error. Pierwszy test rzeczywistego konta wykonuje administrator w panelu.
